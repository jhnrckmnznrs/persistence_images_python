# Controlled persistence-image library comparison

## Mathematical parity protocol

Inputs are deterministic birth–persistence diagrams generated by NumPy PCG64
(seed 93). The birth and persistence values lie within (0,1). The output
is on fixed bounds [0,1]² and a fixed square grid, with Gaussian standard
deviations sigma_x = sigma_y = 0.2. The weight is the bounded ramp
w(p) = min(1,p/0.6).

For the stable pixel-integral comparison, `persim.PersistenceImager`
is configured with `pixel_size=1/n_pixels`, `skew=False`,
`weight="linear_ramp"`, `start=0`, `end=0.6`, and Gaussian covariance
diag(0.04,0.04). This defines the same feature vector as our stable
CDF implementation, up to floating-point error.

GUDHI `PersistenceImage` is intentionally tested **separately**:
its standard implementation evaluates normalized Gaussian densities
at `numpy.linspace(0,1,n_pixels)` sample locations. The GUDHI result
is compared with that independently calculated sampled density, not
with an integrated image. Therefore, **do not compare GUDHI's runtime to
persim's as an equivalent-operation benchmark**.

## Reproducible preliminary measurements

Source: [passing GitHub Actions workflow](https://github.com/jhnrckmnznrs/persistence_images_python/actions/runs/38723499179).
Ubuntu-hosted Python 3.12, NumPy 2.5.4, persim 0.3.8, GUDHI 3.13.0,
OPENBLAS_NUM_THREADS=1. Each timing is the median of **three warmed
repetitions**. Computation timings exclude process start, fitting and
random dataset generation.

| Dataset | Grid | Our direct CDF | Our stable auto | persim integrated |
| --- | --- | ---: | ---: | ---: |
| 200 continuous | 24 × 24 | 0.454 ms | 0.469 ms | 2.709 ms |
| 2,000 continuous | 64 × 64 | 11.616 ms | 1.402 ms | 47.625 ms |
| 2,000 quantized | 64 × 64 | 10.914 ms | 0.439 ms | 47.387 ms |

The maximum persim-versus-direct stable absolute errors were,
respectively, 2.66e-15, 6.52e-15, and 1.89e-14. Our stable-auto
maximum discrepancies from the direct stable reference were 0, 8.27e-12,
and 6.11e-16; the continuous FFT run requested interpolation error
1e-8 and the bound excludes floating-point roundoff.

| Dataset | GUDHI sampled runtime | Error versus sampled Gaussian reference |
| --- | ---: | ---: |
| 200 continuous, 24 × 24 | 1.801 ms | 1.99e-13 |
| 2,000 continuous, 64 × 64 | 118.799 ms | 7.73e-12 |
| 2,000 quantized, 64 × 64 | 120.249 ms | 1.23e-11 |

The GUDHI numbers are **not a like-for-like time comparison** against
our stable integrated representation. They are included to verify
GUDHI's own sampled mathematical convention.

## Limitations

These results concern specific *synthetic* data, grids, Gaussian parameters
and installed library versions. Three repetitions on a shared hosted
machine are insufficient for robust performance inference. They show
promising speedups, not universal superiority.

The entire result directory is uploaded as a GitHub Actions artifact.
The source program is `benchmarks/compare_libraries.py`.
For a publishable study, test different bandwidth ratios, grids, point
counts, number of unique coordinates, process memory, cold/warm caches,
multiple machines, and **real persistence diagrams** with clear provenance.

```bash
pip install -e ".[compare]"
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
python benchmarks/compare_libraries.py \
  --kind quantized --n 2000 --pixels 64 --repeats 5
```
